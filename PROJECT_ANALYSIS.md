## 1. Project Overview

DemSchoolTools is a multi-tenant school management platform serving ~17 Sudbury-model schools. It manages Judicial Committee (JC) records, attendance tracking, student/parent/donor profiles, and the school's management manual.

### Architecture at a Glance

```
┌─────────────────────────────────────────────────┐
│               nginx (reverse proxy)             │
├────────────────────┬────────────────────────────┤
│   Play / Scala     │      Django + DRF          │
│   port 9000        │      port 8000             │
│   (legacy)         │      (modern)              │
├────────────────────┼────────────────────────────┤
│   PostgreSQL       │      PostgreSQL            │
│   school_crm       │      school_crm            │
├────────────────────┼────────────────────────────┤
│   React (legacy    │      React (Vite)          │
│   webpack/HashRouter)  │    createBrowserRouter    │
└────────────────────┴────────────────────────────┘
```

- **Legacy Play/Scala stack**: `app/`, `authLibrary/`, `modelsLibrary/`, `conf/`, `project/` (frozen per AGENTS.md).
- **Modern Django backend**: `django/` with two apps (`dst`, `custodia`), DRF API views, Playwright PDF generation.
- **Modern React frontend**: `react/` with Vite build, MUI components, and a new `SignInSheetPage`.
- **Legacy React frontend**: `react/custodia/js/` — HashRouter-based app loaded on Custodia pages.

## 2. Current State Assessment

### 2.1 Strengths

- **Multi-tenancy**: Well-implemented via `OrganizationHost` → `Organization` lookup, `request.org` enforced throughout.
- **Auth bridge**: JWT-based `PLAY_SESSION` cookie shared between Play and Django. Falls back to IP allowlisting.
- **Configurability**: Per-school terminology via `OrgConfig` subclasses (17 schools with custom JC names, pleas, etc.).
- **Migration in progress**: Django is progressively replacing the legacy Scala stack. New features go into Django/React.
- **Tooling**: Ruff linting, Prettier formatting, ESLint + React Hooks plugin, uv package manager, Vite dev server.
- **Audit trail**: `django-auditlog` is registered on key models (Person, Tag, AttendanceCode, etc.).

### 2.2 Weaknesses & Risks

| Area | Issue | Severity |
|------|-------|----------|
| **Testing** | Near-zero test coverage. `django/dst/tests.py` is a stub (`# Create your tests here.`). No frontend tests. | **High** |
| **CI/CD** | Single GitHub Action that only runs Google Java Format on Scala. No Django/React lint, test, or build checks. | **High** |
| **Deployment** | Manual zip-and-rsync via `build_and_copy_to_server.sh`. No containerization, no orchestration, no rollback. | **High** |
| **Error handling** | `custodia/views.py:login` proxies auth through the Play server. If Play is down, login fails silently. | **High** |
| **Legacy coupling** | Django depends on an external Play server for login/auth. Single point of failure. | **High** |
| **Django settings** | Dev secret key committed (`settings.py:26`). Debug mode commits the key. Not a production issue (overridden in `settings_prod.py`) but a hygiene concern. | **Medium** |
| **Schema fragility** | Models use `db_table` overrides on legacy `public.*` tables. `User` model has `db_table = 'public"."users'` (schema-qualified). Renames/drops could break Scala. | **Medium** |
| **Frontend fragmentation** | Two React apps (legacy Custodia HashRouter, modern Vite BrowserRouter). Different styling patterns, different build pipelines until Vite. | **Medium** |
| **Dependency drift** | `package.json` has separate root-level and `react/package.json`. The root one is for the legacy webpack build. Easy to accidentally update the wrong one. | **Low** |
| **Logging** | `LOGGING` in settings has `disable_existing_loggers: True` which can silence third-party loggers. | **Low** |
| **No feature flags** | `Organization` model has some boolean feature flags, but no systematic feature-flag system for gradual rollout. | **Low** |
| **No migrations CI** | No automated check that `makemigrations` produces no new changes (i.e., all pending migrations are committed). | **Low** |
| **Rollbar token exposure** | `ROLLBAR_FRONTEND_TOKEN` set from env, but it flows to every page's `window.initialData` via `render_main_template`. Should be scoped to admins only. | **Low** |

### P0: Critical (fix in current sprint)

#### 3.1 Add CI Pipeline for Django and React

**Problem**: The only CI is a Google Java Format check. Django lint (`ruff`), React lint (`eslint`), and tests never run in CI.

**Solution**: Add a GitHub Actions workflow:

```yaml
name: CI

on: [pull_request]

jobs:
  django:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_DB: school_crm
          POSTGRES_PASSWORD: postgres
        ports: [5432:5432]
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v5
      - run: uv sync --frozen
        working-directory: django
      - run: uv run ruff check django
        working-directory: django
      - run: uv run manage.py test
        working-directory: django
        env:
          APPLICATION_SECRET: test-secret
          DST_DB_PASSWORD: postgres
          DJANGO_SETTINGS_MODULE: demschooltools.settings_ci  # new CI settings file

  react:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: npm ci
        working-directory: react
      - run: npm run lint
        working-directory: react
      - run: npm run build
        working-directory: react
```

#### 3.2 Add Django Test Suite

**Problem**: Zero backend tests.

**Solution**: Add `django/dst/tests/` and `django/custodia/tests/` packages with:

- Model tests (creation, constraints, `__str__`, custom methods)
- View/auth tests (using `RequestFactory` or `APIClient`, verifying `request.org` scoping)
- Migration tests (verify forward/backward, verify constraints)
- Management command tests (call with `call_command`)
- PDF generation tests (basic smoke test with Playwright)

Example structure:

```
django/dst/tests/
├── __init__.py
├── test_models.py        # Organization, Person, User, UserRole, etc.
├── test_manual_views.py  # Chapter/Section/Entry CRUD
├── test_attendance_views.py
├── test_auth.py           # PlaySessionMiddleware, IP auth
├── test_pdf_utils.py
├── test_commands.py       # setup_initial_data, copy_manual, etc.
└── test_org_config.py     # OrgConfig subclasses

django/custodia/tests/
├── __init__.py
├── test_models.py        # Swipe, Override, Excuse, Year
├── test_views.py          # API views
└── test_sync.py           # sync_custodia_and_dst logic
```

### P1: High (next sprint)

#### 3.4 Containerization

**Problem**: Deployment is manual zip-rsync with downtime. No reproducibility.

**Solution**: Dockerize the stack:

```
django/Dockerfile        # uv → collectstatic → gunicorn
react/Dockerfile         # node → vite build → nginx static
docker-compose.yml       # django + react + postgres + nginx
```

Add a `Dockerfile` for Django and one for React. Add `docker-compose.yml` at the repo root for local development and CI.

#### 3.5 Decouple Login from Play

**Problem**: Django proxies login through the Play server (`custodia/views.py:56-63`). If Play is down, login fails.

**Solution**: Implement Django-native password verification using the bcrypt hasher already configured in `settings.py` (`BCryptPasswordHasher` is listed). Steps:

1. Remove the `requests.post` proxy in `LoginView.post()`.
2. Use `authenticate()` / `login()` from Django auth.
3. This makes Play's auth purely optional for legacy users.

#### 3.6 Production Deployment Automation

**Problem**: `build_and_copy_to_server.sh` is fragile. No zero-downtime deploy, no health checks, no rollback.

**Solution**: Create a deployment pipeline:

- GitHub Actions workflow that runs tests, builds, then deploys via SSH/rsync (or Docker push).
- Add a `run_django.sh` rewrite that uses `gunicorn` with `--preload` and `--reload` for zero-downtime restart via USR2 signal.
- Add health check endpoint (`/health/`) that verifies DB connectivity.

### P2: Medium

#### 3.7 Add API Serializers

**Problem**: `custodia/views.py` manually shapes dicts. Data contracts are implicit.

**Solution**: Create `django/dst/serializers.py` and `django/custodia/serializers.py` with DRF serializers. This makes the API self-documenting via OpenAPI (can add `drf-spectacular` later).

#### 3.8 Migrate Legacy Custodia React to Modern Pattern

**Problem**: Two different React setups with different patterns.

**Solution**: Incrementally port legacy Custodia screens (`StudentTable`, `Student`, `StudentReports`) from the HashRouter setup to the Vite BrowserRouter setup. Eventually remove the `react/custodia/` entry point.

#### 3.9 Add API Versioning

**Problem**: All endpoints live under `/custodia-api/` with no versioning.

**Solution**: Namespace with `/api/v1/...`. Start by adding URL prefix routing, migrate consumers incrementally.

#### 3.10 Django SECRET_KEY Hygiene

**Problem**: Dev key is in source. While replaced in prod, it's a bad pattern.

**Solution`: Remove the inline default. Make settings fail hard if `DJANGO_SECRET_KEY` is not set, even in dev. Add a `.env.example` file:

```
APPLICATION_SECRET=changeme
DJANGO_SECRET_KEY=changeme
```

### P3: Nice-to-Have

#### 3.11 Type Hints Throughout

Python backend uses some type hints but inconsistently. Add `pyright` or `mypy` checking.

#### 3.12 OpenAPI Documentation

Add `drf-spectacular` and generate OpenAPI 3 schema. Serve via a `/api/docs/` endpoint.

#### 3.13 Pre-commit Hooks

Add `.pre-commit-config.yaml` with:
- `ruff check` (Python)
- `prettier --check` (JS/JSX/SCSS)
- `eslint` (JS/JSX)

#### 3.14 Database Migration CI

Add a CI step that runs `manage.py makemigrations --check --dry-run` to ensure all model changes have corresponding migrations.

#### 3.15 Logging Improvements

Change `disable_existing_loggers` to `False`, add structured logging (JSON) for production.

## 5. Deployment Automation Roadmap

### Phase 1 (Current): Manual

```
git push + ssh + build_and_copy_to_server.sh → rsync zip → restart manually
```

### Phase 2 (Current): Scripted with Health Checks + Docker

```
build_and_copy_to_server.sh → rewritten with:
  - ERR trap for early failure detection
  - Pre-deploy git diff check
  - Clear post-deploy steps (migrate, collectstatic, health check)

run_django.sh → rewritten with:
  - Zero-downtime USR2 restart for existing gunicorn process
  - Configurable workers/port via env vars
  - Clean start if no existing PID

docker-compose.yml + Dockerfile → containerized deployment:
  - Multi-stage build (React → Django)
  - Nginx reverse proxy
  - PostgreSQL with health check
  - Environment variable configuration
```

### Phase 3 (Medium-term): Docker + Docker Compose

```
docker-compose up -d
  → django (gunicorn)
  → react (nginx static)
  → postgres (optional, for dev)
  → nginx reverse proxy
```

### Phase 4 (Long-term): Kubernetes / Nomad

- Container registry (GHCR or Docker Hub)
- `deploy/` directory with k8s manifests or Nomad job specs
- Automated rollbacks, blue-green deploys, canary releases

## 6. File-by-File Improvement Suggestions

### `django/demschooltools/settings.py`
- Remove inline `SECRET_KEY`, require env var or default to a dev-only fallback.
- Change `disable_existing_loggers` to `False`.
- Add `DATABASE_URL` parsing via `dj-database-url` or manual decode.

### `django/demschooltools/settings_prod.py`
- Add `SECURE_HSTS_SECONDS`, `SECURE_HSTS_INCLUDE_SUBDOMAINS`.
- Consider adding `SECURE_CONTENT_TYPE_NOSNIFF`, `SECURE_BROWSER_XSS_FILTER`.
- Add `SESSION_COOKIE_SAMESITE = 'Lax'` (already secure via cookie settings).

### `django/custodia/views.py`
- Extract serializers into `custodia/serializers.py`.
- Add `throttle_classes` to API views to prevent abuse.
- Fix the `LoginView.post()` Play coupling (see §3.5).
- Fix the `for` loop in `LoginView.post()` — the `return response` is inside the loop, which only iterates one cookie.

### `django/dst/auth.py`
- Add logging for failed JWT decode (currently just `print(e)`).
- Add rate-limiting for IP-based auth.

### `react/custodia/js/app.jsx`
- Legacy Bootstrap-based UI. Plan migration to MUI/Mantine.

### `react/pages/SignInSheetPage/`
- Add test coverage.
- Lazy-load the `SignInSheetPdf` component (`React.lazy` + `Suspense`) since it imports `@react-pdf/renderer` which is heavy.

### `build_and_copy_to_server.sh`
- Add trap on error.
- Add pre-deploy health check on the current server.
- Add post-deploy smoke test (HTTP 200 on known endpoints).
